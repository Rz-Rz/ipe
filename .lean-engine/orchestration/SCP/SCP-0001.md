# SCP-0001: What an edit, a deletion or a refresh of an accepted object by a non-author actor does

## Intent

SPEC-KER-006 rules the approval state: an object created by the assistant or by an import enters as a proposal, and only an author action accepts or rejects it, including the undo of such a decision. It says nothing about an edit, a deletion or a refresh of an accepted object by an actor other than the author. Under principle P01, nothing becomes accepted manuscript content or an established fact by the assistant's action alone; an assistant edit that leaves an object accepted would let generated content stand as accepted without an author action. The change says what the kernel does in these three cases, so that the requirement covers every gesture that touches an accepted object.

## Scope and non-goals

Touches the text and coverage of SPEC-KER-006 in `dossier-recette/10_PROVENANCE_KERNEL.md` and the kernel domain only. Does not change SPEC-KER-007 (reversibility), does not define the assistant's actions themselves (domain AST), does not change the approval states or their names.

## Proposed modification

Current requirement: "An object created by the assistant or by an import must enter the project as a proposal, and only an author action must change it to accepted or rejected."

New requirement: "An object created by the assistant or by an import must enter the project as a proposal, and only an author action must change it to accepted or rejected, or undo such a change. An edit of the anchors, the title or the body of an accepted object by an actor other than the author must return the object to the proposed state. A deletion or a refresh of an accepted object by an actor other than the author must be refused with not_author and recorded."

Coverage, added: Limit: an edit by the author keeps the approval state. Error: a deletion or a refresh of an accepted object by a non-author actor is refused and recorded; the object is untouched.

| Test | Artefact | Nature | Expected result |
|---|---|---|---|
| TST-KER-006e | planned | unit | An assistant edit of an accepted object returns it to proposed; an author edit keeps it accepted. |
| TST-KER-006f | planned | unit | An assistant deletion or refresh of an accepted object is refused with not_author, recorded, and the object is untouched. |

## Example

The assistant rewrites the body of an accepted fact: the fact shows as proposed in every view until the author accepts it again, with the assistant's edit event in its history. The assistant cannot delete the fact; the refusal is recorded with its actor.

## Recommendation

Accept. The alternative (an assistant edit leaving the object accepted) contradicts P01 in substance; the cost is two cases in the kernel and their tests, inside the kernel domain. A third option (refuse every edit of an accepted object by a non-author) would block assisted revision of accepted notes, which N03 and N05 expect.

## Validation

Acceptance by the operator applies the new text and coverage to the requirements folder and opens a commitment for the two cases, under domain KER. Proof: TST-KER-006e and TST-KER-006f green, and a mutant per case falling.
