## Context

Milestone J-PRV connects an AI provider with access the author supplies (baseline N04: author-supplied API access is always the floor; Appendix A: subscription-backed routes are unverified for a desktop product and must not be presumed). The requirements SPEC-PRV-001 to 007 and SPEC-AST-001 are written for one provider adapter at this milestone, behind a contract that any provider implements.

## What is at stake

The first adapter is the one every test, every screenshot and the first user run exercise. A second adapter costs one package against the same contract; a wrong first choice costs the milestone's user value, since the operator's own access decides whether the product can be used at all on the day it ships.

## Closed question

Which provider does J-PRV connect first: A, B, or C?

## Options and consequences

**A. The Claude provider's Messages API with an author-supplied API key; a second provider in a later commitment; sign-in routes after their eligibility is verified.** The operator's workstation already uses this provider's tooling, so the first user run has a key at hand. The Messages API documents usage per response, which SPEC-PRV-002 needs. Prices and models come from the provider's published pages at a stated date.

**B. OpenAI's API with an author-supplied key first.** Same contract, same cost; the operator's access to a key is not established; Appendix A records a conditional subscription route for locally hosted applications that could matter later for this provider.

**C. Both adapters in J-PRV.** Doubles the catalogue, fixture and live-test work before any user value; the contract is proved by one adapter and a fake provider already.

| Criterion | A | B | C |
|---|---|---|---|
| A key at hand for the first user run | yes (the operator's) | not established | partly |
| Usage reported per call by the API, as SPEC-PRV-002 requires | yes | yes | yes |
| Adapters to maintain in this milestone | 1 | 1 | 2 |
| Subscription route documented for a desktop application (Appendix A) | conditional, to verify | conditional, to verify | both to verify |

## Recommendation

**A.** The contract and the fake provider carry the design; the first adapter should be the one the operator can run on day one.
